## 二、接口详情

### 1. `/health` - 健康检查接口

| 属性 | 值 |
|-----|-----|
| 调用方法 | `_health_check()` :186 |
| HTTP 方法 | GET |
| 超时 | `_health_probe_timeout_sec` (配置项) |
| 成功条件 | `status_code == 200` |

**返回值处理：**
```python
# 返回 bool
True  → 健康检查成功
False → 健康检查失败
```

**错误处理方式：**
- **不抛异常**：仅返回 `True/False`，由调用方决定处理方式
- **调试日志**：失败时记录 `DEBUG` 级别日志（适用于启动重试场景）
- **调用方处理**：
  - `wait_until_ready()` :211 - 重试机制，最多 `max_retries` 次
  - `health()` :259 - 失败计数机制，超过阈值返回 `make_health_fail()`

### 2. `/api/v2/start_infer` - 启动推理接口

| 属性 | 值 |
|-----|-----|
| 调用方法 | `start_infer()` :408 |
| HTTP 方法 | POST |
| 超时 | 60 秒 |

**请求参数：**
```json
{
  "model_version": <int>
}
```

**响应格式：**
```json
{
  "status": {
    "code": 0,
    "message": "..."
  }
}
```

**返回值处理：**
```python
# 返回 bool
True  → 启动成功
# 失败时抛出 Exception
```

**响应解析逻辑：** (`_parse_response_status()` :384)
```python
# 解析 response.json()
result = response.json()
status = result.get("status")
code = status.get("code")
message = status.get("message")

# 判断逻辑
code == 0 → 成功
code != 0 → 失败，返回 message 作为错误信息
status/code/message 为 None → 解析失败
```

**错误处理方式：**

| 错误类型 | HTTP 状态码 | 处理方式 | 监控事件 |
|---------|------------|---------|---------|
| 业务失败 | 200 | `code != 0` 时抛出 `Exception` | `INFERENCE_ROUTER_START_INFER_FAIL` |
| HTTP 错误 | 非 200 | 抛出 `Exception`，包含状态码和原因 | `INFERENCE_ROUTER_START_INFER_HTTP_FAIL` |
| 网络异常 | - | 捕获异常，打印堆栈后抛出 `Exception` | 无 |

**Metrics 上报：**
```python
# 成功
meter.add("paddlerl_inference_router_api_total", 1, tags={"api": "start_infer", "status": "ok"})
# 失败
meter.add("paddlerl_inference_router_api_total", 1, tags={"api": "start_infer", "status": "error"})

# 耗时
meter.observe("paddlerl_inference_router_api_duration_seconds", elapsed, tags={"api": "start_infer"})
```

## 五、RC 启动参数

`InferenceRouterAgent.start()` 方法通过 shell 脚本启动 RC 进程：

**启动命令格式：**
```bash
bash <router_start_script_path> \
    <router_pkg_path> \
    <start_port> \
    <admin_port> \
    <host_ip> \
    <run_path> \
    <node_id> \
    <job_id> \
    <runtime_mode>
```

**参数说明：**

| 参数序号 | 参数名 | 来源 | 说明 |
|---------|-------|------|------|
| 1 | `router_pkg_path` | `config.training_args.environ_base_path` | RC 软件包路径 |
| 2 | `start_port` | 随机分配 (port_range_start ~ mid_range) | 服务端口 |
| 3 | `admin_port` | 随机分配 (mid_range ~ port_range_end) | 管理端口 |
| 4 | `host_ip` | `hostname -i` 命令获取 | 主机 IP |
| 5 | `run_path` | `config.training_args.run_path` | 运行目录 |
| 6 | `node_id` | 构造函数参数 | 节点 ID (从 0 开始) |
| 7 | `job_id` | `config.rollout_args.job_id` | 作业 ID |
| 8 | `runtime_mode` | 根据 node_id 和 nodes_num 计算 | 运行模式 |

**runtime_mode 计算逻辑：**
```python
runtime_mode = "hybrid"      if node_id == 0 and nodes_num == 1
runtime_mode = "scheduler"   if node_id == 0 and nodes_num > 1
runtime_mode = "gateway"     if node_id > 0
```

## 七、响应解析方法

所有业务接口使用统一的响应解析方法 `_parse_response_status()` :384：

```python
def _parse_response_status(self, response) -> tuple[bool, str]:
    """
    解析 RC 响应状态
    
    Returns:
        tuple[bool, str]: (是否成功, 状态消息或错误信息)
    """
    result = response.json()
    status = result.get("status")
    
    # 检查 status 字段存在
    if status is None:
        return False, "failed to parse response status"
    
    code = status.get("code")
    message = status.get("message")
    
    # 检查 code 和 message 字段存在
    if code is None or message is None:
        return False, "failed to parse response status"
    
    # code == 0 表示成功
    if code != 0:
        return False, message
    
    return True, message
```
